# ADR 0002：证据链判定 + unknown 诚实性红线

- 状态：已采纳（2026-09-22）
- 背景：环境诊断工具最大的失败模式是「看起来懂了」——给出模糊结论（「可能是版本不兼容」）或伪造确定性（在没实测时宣称可以运行）。
- 决策：
  1. 每条判定必须携带 `evidence[]`（kind/detail/source）与 `confidence`；
  2. 缺数据时状态为 `unknown` 并说明缺什么，绝不外推；
  3. `--no-verify`（或确认被拒、无 TTY）时 overall 最高只能到 `unknown`，永远不给 `runs`；
  4. 规则/矩阵数据文件必须带 `source` 字段，结论可回溯到官方文档。
- 理由：这是产品信任的根基；使用者要拿结论去决定「是否值得配环境/买机器」，错误的正向结论代价最高。
- 代价：报告里 `unknown` 会比「看起来果断」的工具更多——这是刻意选择，测试（§22-5、test_decide_overall_paths）把红线固化下来。
